# 投递操作手册

本手册说明应用的准备、授权、发送和回执核验流程。它不保存个人履历、候选岗位、登录态、当前平台简历状态或真实投递记录。

## 一、前置条件

| 条件 | 检查方式 | 不满足时 |
| --- | --- | --- |
| 职业档案已确认且现行来源有效 | `check delivery-ready`、简历中心 | 在 App 核对当前资料和来源后重新确认 |
| 发送内容可读且满足该路线的内容契约 | 平台简历读取或固定 PDF 核验 | 显示具体缺项，不猜补个人事实 |
| 岗位与完整 JD 已审核 | Jobs 详情及来源指纹 | 沿原来源重新核对 |
| 未有成功或未决的同岗位投递占位 | 原投递记录与稳定岗位键 | 继续已有流程；未知状态不重复发送 |
| 渠道可用，且该动作在授权范围内 | 原渠道检查与授权记录 | 保持阻断并给出明确下一步 |

所有状态由当前 App 与业务记录读取，不以文档中的历史状态作为放行依据。

## 二、发送路线

### 平台默认简历

1. 在 Jobs 选择经审核的岗位并准备投递。
2. 应用读取平台上当前维护的简历，并核验该路线的内容要求。
3. 用户在既有审批入口确认具体渠道、目标和发送内容。
4. 通过已支持的渠道提交，记录实际尝试与权威回执。

实际发送的是平台维护的内容，不能将本地生成 PDF 的质量结论套用到该版本。

### 原生定制 PDF

1. 通过 Quick Run 生成定向候选，核对来源、责任范围和实际 PDF。
2. 固定 PDF、岗位与审批版本；在具体授权下准备平台附件。
3. 核验附件身份与字节内容，再沿既有流程授权最终发送。
4. 读取业务回执并记录成功、失败或未知；未知状态不自动重试。

平台路径能否发送附件以当前实现和真实契约验收为准；页面存在附件入口不等于目标岗位支持该路线。

## 三、内容缺项处理

- 应用分别展示身份/时间线缺失、来源失效、事实缺口和正文未表达。
- 候选人只补充真实可核实的资料；职责、项目和量化指标不能为了过闸门而编造。
- 平台脱敏字段与实际缺项分别判断，不能把脱敏显示直接当成用户资料缺失。
- 调整内容规则须先核对既有规范、适用路线及真实消费者，不为某份简历增加特例。

## 四、常见阻断码

| 阻断码 | 含义 | 处理 |
| --- | --- | --- |
| `career_profile_unconfirmed` | 档案未确认或来源已变化 | 在简历中心重新核对 |
| `RESUME_CONTENT_INCOMPLETE` | 该路线的必要内容缺失 | 查看具体缺项，在原入口补齐真实资料 |
| `RESUME_UNAVAILABLE` | 平台内容不可读 | 检查渠道会话或凭据 |
| `JOB_REVIEW_REQUIRED` | 岗位未审核或来源指纹变化 | 在 Jobs 重新审核 |
| `ALREADY_ATTEMPTED` | 同岗位已有尝试 | 检查已有流程与回执，不重复投递 |
| `BATCH_ROUTE_NOT_AUTHORIZED` | 批次与发送路线不匹配 | 使用对应授权入口 |
| `BATCH_LIMIT_REACHED` | 授权额度用尽 | 停止本批次 |
| `EXCLUDED_TARGET` | 目标命中已保存排除规则 | 回看具体规则与目标 |
| `PREPARATION_UNAVAILABLE` | 前置准备失败 | 查看具体阶段及原因 |

## 五、投后核验

实际发送版本、岗位身份、授权、投递占位和平台回执必须指向同一笔尝试。反馈沿既有同步/记录入口追加，不补造招聘方回复。个人复盘和平台观察分别标明来源；补证、刷新页面或重新启动应用不能重置防重约束。
