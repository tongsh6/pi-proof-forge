# Benchmark 001 — Rule-Mode Pipeline Baseline

历史观察：2026-05-08。仓库记录保留引擎缺陷和复现方法，不包含个人证据卡、简历正文或其运行评分。当前示例使用明确合成数据；重新运行得到的是当前实现结果，不能冒充原样本复现。

## 机制发现

- 匹配引擎曾只搜索 tags、title、results，没有消费 EvidenceCard.stack，导致技术栈信息存在但关键词覆盖为零。
- 多张卡因此得到相同分数，排序无法区别相关性；生成器随后展开大量事实，不能据此证明选材合适。
- 数字字符、篇幅与 Markdown 列表标记只是形式代理指标，无法证明量化结果或来源真实性。
- 生成可追溯到某张卡，只能证明文字来源关系，不证明该事实已经发生或适合目标岗位。

## 验证方向

独立正反例应分别覆盖技术栈字段实际消费、同词异义、无字面重合的语义支持、未被采用的证据以及来源变化。现行岗位判断以语义评审为主；历史规则问题不构成继续扩大词表的依据。

## 当前合成样例入口

```bash
python3 -m tools.cli.entrypoints pipeline --raw tools/sample_raw.txt --job-profile job_profiles/jp-2026-001.yaml
```

该命令只用于观察应用 pipeline。自动生成的证据、匹配、简历、评分和 run record 是本地运行产物，不提交到应用仓库，也不属于正式投递件。
