# Benchmark 003 — LLM 与规则链路的工程比较

历史观察：2026-05-08。原始运行包含个人职业样本；仓库记录仅保留机制观察，不发布经历原文、候选目标、卡 ID 或个人评分。这里没有用新编的履历替换历史输出。

## 匹配与选材

- 规则读取缺失会造成所有卡等分；修复输入消费只解决该确定性缺陷。
- 语义评审能够表达具体缺口和引用理由，但必须核验引用身份、原文版本及责任范围。
- 选择较少事实并不自动代表更聚焦；应检查它们是否覆盖目标职责，以及独立更优事实是否被提前排除。
- 模型调用的延迟与不确定性需要有界预算、错误语义和有效缓存；不能以规则猜测替代未完成的语义判断。

## 生成与质量

历史输出曾体现格式和措辞差异。字体、加粗或自然表达不能证明事实无新增；必须对照完整来源、正文 trace 与责任/测量限定。未经核实的预测、目标或测试结果不能因改写更流畅而升级为实绩。

## 当前验收方法

通过同一组明确合成材料和 JD，从现有 pipeline 比较被选事实、实际正文、精确 trace、质量缺口以及调用工作量。独立设置正反例，尤其覆盖同词异责、同数字异语义和无字面重合的可支持事实。真实 JD 与本地模型的应用验收另行执行，不把纯模型跑分作为应用结论。

合成样例入口见 [Benchmark 001](benchmark-001.md)，现行正文与结果证据标准见 [简历质量规范](../../openspec/changes/resume-quality-standard-and-evidence-inference/specs/resume-quality/spec.md)。
