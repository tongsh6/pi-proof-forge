### CLI（`python3 -m tools.cli.entrypoints <command>`）

`extract` / `match` / `generate` / `evaluate` / `pipeline` / `agent` / `check` / `kb`。
实现分层：cli → orchestration → engines → domain，infra 为唯一 IO/模型适配层；
`check` 承载架构/路线图/AIEF/投递就绪/BOSS CLI 门禁，`kb` 承载知识索引。

### 质量与信任体系

- 匹配：规则 K/D/S/Q/E/R（可解释分项）+ 语义评审（逐卡/逐要求引用核验，缓存绑定输入指纹）+ 方向评估建议层。
- 生成：确定性模板拼装 + 字段等级/时间精度/行动-成果配对规则；LLM 只做选材（Quick Run）或受控改写（Agent，数字/实体/长度程序化校验，违规回退模板）。
- 评测：四层质量报告（合格/对位/优质/突出）+ 投递建议 + 缺口任务；PDF 页面校验。
- 投递：原生猎聘 PDF 流程（渠道会话 → 单次授权 → 上传 → 最终确认 → 回执核验 → 反馈同步），每日合计最多 3 次确认成功投递。

### 已知边界

- 不支持全自动投递；最终发送必须用户确认（宪法硬门禁）。
- BOSS/智联/51job/脉脉/拉勾无官方 API/CLI，当前人工导入；在线只读暂 blocked。
- Agent 链路不使用 Quick Run 的语义选材策略（生成策略为 template + 受控改写）。
- 验收工具层（`tools/acceptance/`）仍为大体量单文件（已记录 R6，不影响业务使用）。

- 质量阈值 `config/quality/thresholds.yaml`：`eligible_max_pdf_pages: 2`，3 页会判 R1.5 失败；
  而 core spec 排版条款为「一页优先，以完整可读为准；长经历允许自然续页，禁止缩字/截断正文」——
  两者对 3 页的处置需要产品决策：按 spec 允许自然续页，或在渲染层按 JD 相关度裁剪历史职责。
- 自动尝试结论：将每段职责压缩到 1 条、删除「所属工作」行、历史段精简、核心能力/项目 bullet 上限
  等都无法把内容量降到 2 页（约需裁剪 700+ 字符，会明显损失内容）；2 页目标需用户在 App 内选择
  更少选材卡，或后续按 JD 相关度做智能裁剪（产品决策，非本轮自动改）。已落地的密度规则：
  工作经历每段职责 ≤2 条、核心能力 ≤3 组、项目 bullet ≤3 条/卡。
- R3.2 量化缺口实测：最终版 11 条 bullet 中 4 条带量化（规则判定 0.375，阈值 0.4），差约 1 条；
  量化证据集中在亚玛芬卡，团险/运动中心卡无量化成果——需补充量化证据卡（不能编造），
  或在 App 内换用含量化结果的选材。
