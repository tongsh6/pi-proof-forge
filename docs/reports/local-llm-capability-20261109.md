# 本机推理后端的应用接入观察

历史观察日期：2026-11-09。本文保留语义评审的协议与失败机制，不纳入个人证据池、岗位正文、运行批次和评分。历史后端观察不代表当前默认模型选择，也不构成本次应用验收。

## 任务约束

语义评审采用判定与取证分离：模型输出事实编号 `fact_id` 与判断，程序从已绑定的证据源转录原文。结构化 JSON 合法只能证明格式成立；编号、原文版本和实际来源必须另行核验。自由文本流畅不能补足无效引用。

## 历史工程观察

| 场景 | 对应用的影响 | 处理边界 |
| --- | --- | --- |
| Strata 后端的 `iq3_s` 生成了可解析结构，但不能稳定保持精确事实编号 | 引用验证报 `semantic_invalid_citation`，评审须保持失败或降级范围 | 不能将语气可信的分析当成已核实证据 |
| LM Studio 后端的结构化响应需要适配 `json_schema` 与推理设置；长输入曾触发 HTTP 错误 | 格式支持、事实引用和服务稳定性是三个独立条件 | 保留明确错误与请求预算，不凭一次成功推广为默认可用 |
| Ollama 后端的推理输出可能耗尽正文预算，长任务可能超时 | 空正文和超时均不能伪装为完整语义结论 | 显式传递推理配置、输出预算、超时与失败范围 |
| 规则生成链路能独立完成确定性处理 | 只能证明该链路可运行 | 规则可运行不等于岗位语义匹配、定向选材或事实保真已经成立 |

## 当前验证方法

- 从应用现有 pipeline 调用项目本地模型 Splash，检查完整 JD、事实选择、正文 trace、质量结论和可观察错误，而非独立模型跑分。
- 用明确合成资料先覆盖有效编号、无效编号、来源变更、空正文、超时与重试边界。真实资料和 JD 的验证只在相应授权范围内进行，结果留在本机数据区。
- 缓存复用必须绑定实际输入与来源版本；失败不能转成默认通过，尚未评估的事实不得冒充评审结果。
- 任何批大小或分段优化须保留完整命题与条件，并通过应用行为证明没有漏掉更相关证据。

当前真实 JD + Splash 的内部预览、正式简历质量与实际投递验收状态，以执行路线图和本机授权记录为准；本报告没有新增这些完成声明。
