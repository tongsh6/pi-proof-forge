# 简历生成（Generation）

## 目标
- 模板优先拼装，确保事实不被改写。
- 受控改写只做措辞与关键词对齐，不新增事实。
- 输出可版本化（resume_version_id）。
- App 应沿既有材料导入 → 证据提炼/审核 → JD 画像/匹配 → 选材 → A/B 正文/PDF → 质量反馈完成生成。资料足够时目标为 15 分钟内产出；导出 PDF 只是中间结果，成品还须通过内容与视觉验收。
- 经历展示场景、本人职责、时间、具体行动与结果/产出；需求、方案、测试结果和生产业绩不互相升级。缺角色/时间/技能/行动时返回具体补证据项，不编造填充，不把历史未审核卡直接加入候选池。

## 固定结构（1 页优先）
下列数量为建议；以事实完整和可读为准，长内容可自然续页，不能删掉关键事实或强行缩小字号。
1) 顶部 10 秒区：定位 + 核心标签 + 技术栈
2) 核心亮点 3 条：结果 + 场景 + 动作
3) 工作经历：每段 4–6 bullets（动词 + 影响面 + 方法/约束 + 结果）
4) 代表项目 3 个：挑战-动作-结果
5) 开源/工具/内容（可选）

## 完整简历内容标准（2026-10-05 已确认实施）

用户要求先梳理完整简历应有的内容，再进行投递，并已明确开工。以下为本次实施标准，补充上述既有目标；各模块的实际完成情况以台账为准。完整职业档案、正文组织、版本审核与投递门禁沿现有链路补齐。

| 模块 | 应有内容 | 必要性与事实来源 |
| --- | --- | --- |
| 基本信息与求职方向 | 姓名、有效联系方式、所在/意向城市、明确目标岗位；作品链接按需 | 必需；来自用户确认的个人资料 |
| 职业摘要 | 职业方向、相关经历与职责层级、业务领域、最有依据的优势；3–4 句概括 | 推荐；由已确认工作履历及证据归纳，不凭目标 JD 推断资历 |
| 核心能力与技能 | 按技术开发、架构/数据、工程交付、协作管理等相关领域分组，说明实际应用能力及依据 | 核心模块；只展示有经历支撑的技能，是否有管理经历以事实为准 |
| 工作/合作经历 | 实际任职公司、部门/岗位、起止年月、职责边界、业务范围与主要贡献 | 必需；独立维护职业时间轴，再关联证据卡；客户品牌与任职公司不能混用 |
| 代表项目 | 项目归属与时间、本人角色、业务目标/约束、关键行动与技术取舍、实际结果及证据 | 核心模块；按目标选取，通常 2–4 个为展示参考，不强制凑数，不重复堆砌工作经历 |
| 教育背景 | 学校、专业、学历/学位、起止时间 | 基础档案；如实收集，用户可明确选择不展示；岗位有相关硬要求时说明是否满足，不从 JD 回填 |
| 其他可验证成果 | 开源、作品、专利、文章、证书、语言能力、奖项 | 可选；存在真实且相关的依据才展示 |

每段核心经历至少回答：场景是什么、本人负责什么、解决了什么问题、采用什么方法/取舍、形成了什么结果。设计方案、测试验收、生产上线及业务收益分别表述；没有量化指标时可写可验证的定性成果，不强造数字。

### App 的组织方式

- 职业档案保留完整基础履历；证据库保存更细的项目事实与原文；针对完整 JD 生成具体版本。复用现有简历中心、材料库、证据审核、画像和匹配，不重复建库。
- 完整底稿与岗位定制版分开：底稿先确认身份、时间轴、职责及成果，定制版选择相关项目/能力和顺序，不能改变履历事实。
- 一页优先仅为排版偏好；多年经历可用两页，以信息完整和可读为准，页数不作为质量达标的替代指标。

### 投递前内容验收

1. 完整性：基本资料、清楚的职业时间轴、职责及代表经历具备；用户明确不展示的可选项与尚未采集的缺项区分。
2. 真实性：具体贡献与成果有材料或用户确认支撑；无虚构资历/数字/技术，个人贡献与团队成果区分，时间和归属无矛盾。
3. 岗位针对性：有完整 JD，能解释选材原因、满足项及真实差距；摘要、技能、项目围绕目标组织。
4. 文档质量：没有空章节/占位文字/内部审计信息，阅读顺序清楚，PDF 无截断或乱码；正文和批准版本一致。
5. 用户审核：用户确认目标岗位及最终简历版本后才能进入投递授权；生成完成、规则分数和历史发送成功不能代替上述验收。

## 生成流程（强约束）
1. 召回证据卡
2. 排序并选 Top N
3. 模板拼装（事实字段锁定）
4. LLM 受控改写（仅措辞/关键词）
5. 生成版本号 `resume_version_id`

## 输出版本
- 版本 A：偏架构/技术深度
- 版本 B：偏交付治理/Owner

## 事实保真规则
- 不允许新增指标、范围、职责或角色级别。
- 所有关键表达必须可追溯到 evidence cards 字段。

## 可配置项（建议）
- 模板样式与版式
- 关键词对齐策略
- 受控改写的允许变更清单

## LLM 辅助模式
- CLI：`tools/run_generation.py --use-llm`
- Prompt：`tools/prompts/generation.md`
- 严格模式：`--use-llm --require-llm`（LLM 不可用即失败）
- 当前 Quick Run 增量将 LLM 输出约束为现有证据 ID 的选材/排序；正文由选定事实字段拼装，禁止将自由生成文本直接发布为简历。

## 当前实现状态
- 默认使用模板化规则拼装（A/B 两版可复现）。
- `--personal-profile` 接入个人资料，`--job-profile` 接入目标公司与完整 JD，`--resume-positioning` 接入定位；默认个人资料为 `personal_profile.yaml`。
- `--use-llm` 打开时使用 LLM 选材；非严格模式失败时记录规则回退，严格模式直接失败。
- 每版 Markdown 同目录保存 `.trace.json`，记录正文/输入指纹、字段来源和待补信息。候选人正文不写入内部追溯标记；导出 PDF 后仍需人工审核事实和岗位适用性。
