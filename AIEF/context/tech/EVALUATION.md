# 质量评测（Evaluation）

## 目标
- 输出可执行的质量评测与改进建议。
- 发现缺口并生成补证据任务。

## 指标（Scorecard）
- 岗位关键词词面覆盖率（只统计 `keywords`，大小写无关去重；完整 `must_have` 另列待核对）
- 量化占比（有指标单位和结果/范围含义的条目；排除纯日期、活动名、技术版本号）
- 空话率/重复度（泛词、同义重复、无主语无结果）
- 篇幅参考（字符/行数规则仅供参考；实际 PDF 分页与信息密度另作视觉检查，不强制一页）
- 证据引用检查（Quick Run 核对独立 trace 的正文/输入指纹，再逐条核对 bullet 的个人资料/证据来源）

## 输出
- Scorecard（总分 + 分项）
- 改进建议（按优先级）
- 补证据任务队列（可自动生成）

## 规则约束
- 所有指标必须可解释与可复现。
- 缺口建议必须指向具体 evidence card 字段或新卡需求。
- 词面命中不证明学历、年限或复合条件满足；硬性条件保留原句和词面线索供核对，不鼓励为了覆盖词语而补写不存在的经历。
- 求职意向（含 Markdown 标签/章节）不计为候选人能力；英文词使用完整词边界，技术栈加号可作分隔符，但 `C` 不等于 `C++` / `C#`。无关键词时使用中性分并明示未配置。
- 数字或技术词不等于引用。Quick Run 缺失或过期 trace 的引用分为零；岗位描述/自定义求职定位不作个人事实来源。JSON 与 Markdown 同步输出关键词命中/缺失、硬性条件待核对和逐条追溯结果。

## LLM 辅助模式
- CLI：`tools/run_evaluation.py --use-llm`
- Prompt：`tools/prompts/evaluation.md`
- 严格模式：`--use-llm --require-llm`（LLM 不可用即失败）

## Quick Run 语义模式（2026-10-12）

- 页面默认语义模式，证据列表读取所有游标页，用户实际勾选的全部合格卡分批进入模型。CLI 的 `--llm-max-cards` 在此模式表示每批上限，默认 8；原文规模超过一批预算时自动缩小批量，不丢卡。
- 匹配结果新增 `.semantic.json`：全卡相关度、逐 JD 要求的 supported/partial/insufficient/conflict、事实 ID 与原文引用、输入指纹、模型/版本、调用及缓存统计。响应 schema 与程序双重限制完整性、来源和长度。
- 请求发送事实 ID、原文和本人职责范围，原始 source/field 元数据留在本地结果；模型 JSON/引用无效最多纠错一次，二次失败则阻断；网络超时不自动重试。缓存和语义产物含原文，只在本机生成并由 `.gitignore` 排除。
- 生成复用已验证选材，不重复调用模型；评测复用逐项判断，并对照正文 trace 判断哪些引用已呈现。原文存在与模型语义判断分别说明，正文未呈现为 not_present。
- 岗位适配与简历覆盖按 supported=1、partial=0.5、其他=0 计算要求支持度；这不是录用概率。表达质量只归一化原规则中的量化、清晰度、篇幅与引用分，关键词单独展示为辅助指标。
- 语义质量通过需全部要求已支持且呈现、事实完整、追溯有效、PDF 就绪与表达质量达到原 78 参考线，最终仍待人工审批。模型失败、语义报告/输入变化或引用失效时严格失败，不能由旧解释模型替代。
- 所有来源仍取原字段，不推断项目日期、本人角色、学历或语言能力。模型判断须供人工核对；证据不足不等于能力缺失。

同日真实多岗复核：职责解析补充“背景与能力要求／任职条件／加分经历”三个明确终止标题，避免将任职条件重复统计为职责；仍为整行标题匹配。串卡错误返回事实ID及期望来源（各限160字符），供现有一次纠错定位，不接受跨卡引用。非编号职责仍可能未被识别，界面报告实际范围；人工岗位适用性核对须另读完整JD，不把这种分数当完整岗位结论。

来源事实附带已确认角色范围。只有技术/职务标签、或引用项目缺本人职责时，不能给完整个人实践支持；引用有效但理由将“参与或负责/主导或深度参与”升级为全部主导时，保守降为部分支持并改写为需核实责任范围，原为不足/冲突的判断不提高。该限定从同卡场景、职责和行动继承，结果字段不能绕过；合法否定说明不误杀，无效引用仍阻断。正文覆盖允许同项目stack在已验证行动中明确呈现，不跨项目或跨技术名混算。

固定PDF候选保存质量快照及摘要，绑定正文、PDF和Scorecard指纹，并把质量摘要纳入既有manifest；审批页分别显示匹配、覆盖、表达参考、事实完整、自动质量状态和本版缺口。历史未保存这份绑定的记录显示“未记录”。原人工批准动作记录所接受的质量快照/缺口，不扩大平台授权，也不改变规则模式本来的通过条件。
- 默认使用规则计分（可复现）：覆盖率、量化占比、空话/重复、篇幅、证据引用。
- 没有语义匹配产物的兼容 CLI，`--use-llm` 仍只追加解释层；Quick Run 语义链路使用上节独立指标，不把旧规则总分当岗位适配。
- 上述 CLI / Quick Run 追溯口径不代表 Agent 简化规则评测已完成同样迁移；Agent 本轮只复用关键词覆盖函数，其规则门禁通过仍不等于完整简历质量通过。
