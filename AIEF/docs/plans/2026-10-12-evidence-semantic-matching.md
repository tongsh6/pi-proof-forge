# P0-026：证据约束的语义匹配

用户已同意将语义匹配作为岗位判断主要依据，关键词保留辅助，事实字段继续严格校验。

现有 Quick Run 使用 CLI 兼容链：`run_matching_scoring → run_generation → run_evaluation`；Agent 另有 hybrid evaluator。本轮复用前者、已配置 Qwen、LLMClient 的 JSON schema 支持、独立生成 trace 与现有结果区，避免新建业务流水线。

1. 核心语义校验放在 matching engine：事实 ID、逐卡/逐要求完整性、原文引用、状态和分数范围。IO、缓存与本地模型请求放 infra；CLI 只负责组装与产物交接。
2. 逐卡召回按原文大小及批量上限切分，全部卡都有判断。汇总阶段保留各要求关联的引用和已确认职业事实，以结构化 JSON 返回要求状态；上游无事实不能靠模型生成事实。
3. 模型返回的选材与引用经校验后写 YAML + `.semantic.json`，记录输入指纹、版本、调用次数/耗时；生成读取已校验选择，评测复用结果并对照实际正文 trace，减少重复调用。
4. 结果区将岗位适配、简历覆盖和表达质量分开，逐项展开来源。默认语义模式；规则模式继续用于回归。DESIGN 与 .pen 同步既有 Quick Run 结果区。
5. 先失败测试覆盖无关键词同义表达可选中、全部卡遍历、伪造/错卡引用、要求遗漏、缓存失效、简历未呈现不得通过、严格失败不回退。跑相关回归/构建，独立审查，四岗本地真实模型复测；原授权、源资料、历史产物不变。
