# P0-026：证据约束的语义匹配

用户已同意将语义匹配作为岗位判断主要依据，关键词保留辅助，事实字段继续严格校验。

现有 Quick Run 使用 CLI 兼容链：`run_matching_scoring → run_generation → run_evaluation`；Agent 另有 hybrid evaluator。本轮复用前者、已配置 Qwen、LLMClient 的 JSON schema 支持、独立生成 trace 与现有结果区，避免新建业务流水线。

1. 核心语义校验放在 matching engine：事实 ID、逐卡/逐要求完整性、原文引用、状态和分数范围。IO、缓存与本地模型请求放 infra；CLI 只负责组装与产物交接。
2. 逐卡召回按原文大小及批量上限切分，全部卡都有判断。汇总阶段保留各要求关联的引用和已确认职业事实，以结构化 JSON 返回要求状态；上游无事实不能靠模型生成事实。
3. 模型返回的选材与引用经校验后写 YAML + `.semantic.json`，记录输入指纹、版本、调用次数/耗时；生成读取已校验选择，评测复用结果并对照实际正文 trace，减少重复调用。
4. 结果区将岗位适配、简历覆盖和表达质量分开，逐项展开来源。默认语义模式；规则模式继续用于回归。DESIGN 与 .pen 同步既有 Quick Run 结果区。
5. 先失败测试覆盖无关键词同义表达可选中、全部卡遍历、伪造/错卡引用、要求遗漏、缓存失效、简历未呈现不得通过、严格失败不回退。跑相关回归/构建，独立审查，四岗本地真实模型复测；原授权、源资料、历史产物不变。

## 2026-10-13 成品反查后的后续切片

工程观察：跨文档补证、原文事实优先级、同项目精确重复和固定 PDF 质量摘要已进入既有实现；真实候选、履历、材料数量和个人评分只留本地。历史问题包括串卡诊断不足、职责章节越界、责任强度升级，以及证据已经存在但没有进入正文。对应代码回归不能替代目标岗位的 App 产物验收；当前完成状态以台账与任务队列为准。

下述切片安排的是应用的来源整合、正文取舍和评估职责，不表示个人候选已经通过验收。复用现有 App 路径，开发脚本只作诊断和回归，不能代替真实资料审核与简历生成。

1. **先把已有确认事实整合成可用证据。** 复用材料文档、证据重审与职业档案关联，补上同一项目的跨文档字段来源与冲突预览。角色、时间、行动、结果分别可追溯；人工确认的覆盖值也记录依据。区分年份精度、完整年月和验收事件日期，“2022–至今”不能补造一月。保留“参与或负责”、个人项目/公司项目、本机验证/生产、计划/完成的边界。不要为通过展示校验放松真实性；未知部分明确保留。验收：同一项目可在 App 核对多个来源并保存，重启读回一致；冲突不能静默覆盖，来源变化使相应评审失效。
2. **让目标简历能够选择和精简。** 将完整职业档案与当前版本实际展示内容区分，复用现有事实 ID、模板和 trace；保留必要身份与任职时间线，但不再要求逐条复制全部贡献。选材按完整 JD 的职责、要求及新增证据覆盖排序，逐项评估后仍可调整代表项目，不以填满三张为目标；同一事实允许在正确来源绑定下压缩、合并或换章节，不得增强责任/成果强度。保留已证实的技术栈呈现，压缩重复背景，将确有来源且与目标职责相关的实践放到读者容易找到的位置。验收：新稿不再因字段齐全自动选入没有需求支撑的项目；删减早期冗余不触发事实缺失，新增或夸大的事实仍被阻断。
3. **修正评估与审批的信息。** 逐项检查复合要求、角色强度及证据阶段，区分“未证明”“已有证据但未展示”“同一事实已通过其他字段展示”；不能用引用存在或职务名称替代能力证明。数字活动名、技术版本不计作成果量化；表达检查覆盖语义重复和实际 PDF 版面。固定 PDF 审批页携带同版本的覆盖、表达和具体缺口，事实完整、自动质量通过与人工接受缺口分别显示，不把匹配分当作总质量。
4. **用同一真实岗位验收 App 产物。** 新版从 App 完成资料审核、Quick Run、逐项来源核对与 PDF 预览；逐页检查第一屏定位、信息密度、相关项目顺序、AI 实践边界、任职时间及来源一致性。与旧固定版本对照，不覆盖历史快照；篇幅按 HR/技术阅读目的决定，不以堆分、硬压一页或完成上传作为质量通过。每个切片先补对应失败测试，按受影响范围回归；需要结构性 UI 变化时同步既有设计规范和图稿。以上修复和质量验收先于追加投递，新的平台写入仍沿已有具体授权路径。
