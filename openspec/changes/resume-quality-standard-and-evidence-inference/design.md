# Design: resume-quality-standard-and-evidence-inference

## 1. 总体思路

三个弱点是一条依赖链，但实施顺序反过来：**先定标准 → 标准反推证据字段与等级 → 再改提炼与生成**。否则补卡没有"够不够"的判据，改生成没有"好不好"的判据。

```
 ┌──────────────┐    反推字段/等级     ┌──────────────────┐    提供材料     ┌──────────────┐
 │ 质量标准(R1-4)│ ───────────────────▶│ 证据可信等级(L1-5)│ ◀────────────── │ 材料库 + kb   │
 └──────┬───────┘                     └────────┬─────────┘                 └──────────────┘
        │ 质量报告                               │ 推断候选 → 用户确认
        ▼                                       ▼
 ┌──────────────┐    等级降级措辞       ┌──────────────────┐
 │ 分层评估器    │ ◀─────────────────── │ 生成器(模板+改写) │
 └──────────────┘                      └──────────────────┘
```

## 2. 现有能力与复用点

2026-10-20 提示词接续：公共产品语境集中在 `tools/prompts/context.py`，由现有 `LLMClient` 统一加入 system 消息；不复制用户口语，不让资料正文成为指令。职责归属结合上下文主动分析，不以字面第一人称作为唯一门槛；待确认推断、已审核事实和岗位要求保持各自用途。公共语境内容指纹参与四类已有缓存，质量判项有界接收 actions 并将完整行动字段纳入缓存指纹。

## 3. 质量评估器设计

### 3.1 模块

`tools/engines/evaluation/tiered_evaluator.py`（新），实现 `EvaluationEngine` 协议，返回 `Scorecard` 扩展字段 `quality_report`。内部四个纯函数各判一层，便于单测：

```
evaluate_eligible(resume, profile, career_profile, cards, trace) -> TierResult
evaluate_fit(resume, semantic_review, jd_items, first_screen) -> TierResult
evaluate_strong(resume, cards, filler_lexicon) -> TierResult
evaluate_distinct(resume, jd_items, cards, highlights) -> TierResult
```

- 首屏定义：Markdown 正文按模板的 `<!-- first-screen-end -->` 标记切分；PDF 渲染后用页面高度二次校验（已有两页无裁切检查）。
- 量化判定：按 `resume-quality` R3.2 与 `evidence-provenance` R5，仅消费 bullet 实际呈现且经精确 trace 核验的同一完整结果事实及其现行实测核定；同卡相同数字、results 字段归属或唯一引文均不能单独授予量化资格。完整命题与测量发生性核定尚未实现，现行比例不得解释为实测标准已经达成。
- 空话词表：`config/quality/filler_lexicon.yaml`，中英文，可由用户编辑。
- LLM 判项（R1.4、R2.1、R3.1、R3.5、R4.1）走受控 JSON：输入 bullet 列表 + 证据卡摘要 + JD 条目，输出必须含引用；缺引用的项按失败处理。缓存键 = `resume_sha256 + job_profile_id + cards_fingerprint`。

### 3.2 突出点提名

```
候选 = { card ∈ 正文使用卡 | 存在 jd_item 使 card 支撑 jd_item 且 exceeds(card, jd_item) }
exceeds 维度：规模(数量级/并发/品牌数)、难度(根因/迁移/高可用)、范围(跨团队/跨品牌)、稀缺组合(JD 两项以上同时满足)
过滤：time_range.level ∈ {L1,L2} ∧ role_scope.level ∈ {L1,L4}
排序：exceeds 维度数 > JD 条目权重 > 置信度
输出：top-2，附理由与引用
```

用户否决写入 `app-data/quality_decisions.json`（按 `resume_sha256`），重算时排除。

### 3.3 与审批页/Quick Run 的接口

- Scorecard JSON 增加 `quality_report`；RPC 响应不破坏现有字段。
- 审批页：四层折叠区，每条 failure 可点击跳到 bullet 或卡；`legacy_scores` 置于折叠"对比"区。
- `readiness.quality_passed = quality_report.auto_pass`；`reasons` 由 failures 生成，不再写"低于参考线 78"。

## 4. 证据推断设计

### 4.1 单文档提炼增强（L1/L2）

`_llm_draft_prompt` 增加 `document_metadata` 段：

```
# Document metadata (for date inference only; do not treat as content)
path: materials/sample-project/2023/08/2023-08-15.md   # 合成示例
filename_dates: [2023-08-15]
first_heading_date: 2023-08-14
modified_at: 2023-08-16
employment_window: 2022-06 ~ 2024-03   # 来自已确认档案，按材料所属公司
```

提示词改为：时间若原文明示 → `time_range` + `provenance.level=L1` + 引用句；否则若元数据可推 → `level=L2` + 引用元数据键；否则留空。角色同理但只允许 L1（上下文主体明确，包括人物/角色章节，不要求逐句出现“我”），跨文档归属的 L3 由 4.2 负责。

### 4.2 跨文档推断（L3）

新 RPC `evidence.inferFields`：

```
输入: card_ids[]（默认 = 分流为"值得补"且缺字段的卡）
步骤:
  1. kb 索引检索：优先已精确绑定且指纹一致的原文，再按卡标题/背景相关性排序（限 20 篇，排除设计资料类来源）；不使用私人材料白名单或派生标签授予优先权
  2. 聚合：保留每篇前 1000 字符及截断标记、日期线索、第一人称关键句与计数；计数只是辅助，不裁掉省略主语的原文语境
  3. LLM 一次调用：输入聚合结果 + 卡摘要 + 关联的已确认任职职责 + 任职区间，输出 time_range/role_scope 候选、等级 L3、置信度、每条依据的 document_id+excerpt
  4. 校验：时间在任职区间内；依据 excerpt 可在文档原文回读；否则丢弃该候选
输出: candidates[] 写入 app-data/evidence_inference.json（按卡指纹 + 文档集合指纹 + 已确认任职上下文 + 公共指令指纹 + 任务版本）
```

不写卡。对账面板新增"待确认推断"列：接受 → `evidence.update` 写字段与 provenance；修改后接受 → L4；否决 → 记录 `(card_fp, candidate_hash)`。

### 4.3 生成器消费等级

正式生成与 Agent 已共用 FactIndex、事实选材、ResumePlan 及正文/trace；`template_assembler.py` 按明确输入路径适配同一生成核心，旧自由正文改写策略及 `llm_rewriter.py` 已删除。按 2026-10-20 用户修订，已采纳的 L3 职责、行动和限定保持原义，来源等级不再机械决定“负责人/参与者”；时间继续按 `precision` 及有效来源等级约束呈现。

### 4.3.1 逐事实正文与结果证据边界（P0-026）

正向措辞方案仍需下述实施前验证；结果真实性的职责和验收口径已对齐到现有 `evidence-provenance` R5 与 `resume-quality` R3.1/R3.2。规范对齐不代表测量核定或正向范围正文已经实现。

隔离合成链已观察：同卡中，明确为本人在测试环境实现的干净续跑动作、同事负责的另一页面、以及只核了测试但原句还称“独立上线生产”的动作，均经现有复审存下各自的范围。正式计划和内部片段都保留独立普通兄弟事实，但不呈现上述范围动作；单独引用其中任一动作时，内部片段无可呈现事实。前者是可用信息损失，后两者是防止误归属和状态升级所需的负控，不能整体解除过滤。

**首选验证的最小变更**：如能建立正文依据，在现有逐事实复审绑定下为同一 `actions/results` 位置保留一条可选、独立可成立的精确原文陈述，复用原 Fact ID、已定位来源片段/文档修订，以及该事实的已核定归属、对象、环境和实现/发布状态。不增事实实体、审核队列或任务级授权。只有现有材料足以核对完整措辞、但缺少该句的现行采纳依据时，才考虑在同一事实复审中一次显式采纳，复用已有修订与撤销；材料无法证实时不能靠点击补足，不逐 JD 复审。应用依据 JD 自己决定是否选用，正式生成与内部片段只消费同一来源和同一完整陈述，不自动改写、拼接、去掉限定词或借用整卡身份。每份成品的现有审批仍独立。

**不开放的条件**：位置/引用有效、已有逐事实采纳，均不能单独证明整句没有夹带更强主张（写入“仅测试”标签也不能抵消句中“生产上线”）。下一实验应先用下列固定正反例证明有可执行方式区分独立已核陈述与混合句。若可选声明仅是任意自由文本、需要用关键词/同次模型自证才能放行、或无法保留已证限定，则继续以现有缺省方式仅留原证据/审计，不进入个人正文，也不阻塞不相关事实。未据此批准接口、存储字段、渲染更改或真实验收。

1. **独立本人动作**：源文有一条完整可独立验证的本人测试环境实现续跑陈述；源、归属和环境全对应且该句是唯一被当前 JD 合法选中的正向事实时，两路各输出一次同一原句，测试限定保留，发布未知不成为上线声明。
2. **同卡角色互不继承**：本人牵头平台、同事实现页面可同时为真；只保留确有独立依据的本人贡献，不把同事页面归给本人，独立无范围兄弟事实仍按原路径呈现。
3. **混合超范围**：测试已实现但完整原句还断言独自负责或生产上线，原句不进两路正文；只有独立出现在原文、另有完整依据的较窄陈述才可能呈现，不自动截断、清洗或拼接。
4. **极性和阶段**：已实现“续跑尚未落库的对象”可按其动作正证呈现；计划、未实现、归属冲突或未知不得生成实现成果。已实现但未发布与发布未知不混用，不由文本词形推定事实。
5. **现行来源与回退**：引用位置不唯一、原文或来源修订变化、复审撤销、同一作用范围出现矛盾、或有篡改的行定位时，两路都拒绝此陈述，保留记录和缺口；不得改用旧文本或兄弟证据补成原声明。
6. **可核查交付边界**：两路均能从确切渲染行定位同一原 Fact、范围及来源修订；未采用的陈述不计入正文覆盖。未因新增声明产生审批、导出就绪或发送，D5 仍需独立真实 App 验收。

**结果属性的独立对照（规范对齐前的复现）**：当时的 [R3.2](specs/resume-quality/spec.md#r3-优质表达) 实现把能回溯到证据卡 `results` 的数字计作可验证量化。以相同 P95 200 ms → 120 ms 分别制作受控实测、预测、目标和仅从“模拟假设”中抄取数字断言的卡，通过实际保存、生成和评分：四例均入池、进入正文并通过文字追溯，全文量化均为 0.50；该隔离样本均未通过整体资格检查。追溯只证明文字出现在哪里，不能证明整句表达的结果已经发生。

- **测量语义验收**：受控实测的完整陈述保持对象、指标及测试条件，实际出现且可追溯时才计入量化，不能升级为生产效果。相同数字的预测、目标、未知均不算已达成绩效；截掉“模拟假设”限定的句子不能当作实测进入正文。可证的已完成非数值交付仍可作为结果，不因缺数字失去资格，只不计量化。
- **证据与回退**：正文与量化若按此改进，须消费同一条已核定、可追溯到原 Fact 和现行来源修订的完整陈述，不从整卡 `results`、词形、已实现/已发布或旧记录自动推得“已测量”。旧的未核定内容保持可读、可复核，保留原材料；不能迁就旧评分而把它计作实测，也不为此批量删除。完整陈述及发生性核定须在现有复审边界产生，并由正文与评分共同消费；本次只对齐规范，没有改变评分的测量语义实现，也没有新增表示字段。

**2026-11-21 已修复的独立边界，不视为实测验收**：`901805a` 使 R3.2 按已渲染的 `results` 来源而非整卡结果计数；`a142c5e` 进一步要求精确追溯版本、实际行号和字段索引对应的 Fact ID。仅渲染同文 `actions:0` 的负控从 1.0 降为 0.0；精确渲染 `results:0` 的正控仍为 1.0。没有修改实测判定。另用当前纯函数对同一卡、相同 P95 数字的四条**完整**陈述（测试环境实测、容量预测、预设目标、模拟假设）逐条传入准确的结果 Fact ID 与行号，四条的首屏/全文 R3.2 都仍为 1.0，且优质层单独通过。这仅证明现行量化口径无法区分结果属性；未运行这四例的 App 全链路、未检查其来源材料，也不代表整体 `auto_pass` 或投递授权。

**源文限定词被截断的独立复现（仅来源校验纯函数）**：同一份合成文档同时包含“规划阶段：预计 P95 从 200 ms 降至 120 ms”和“压测阶段：在测试环境实测 P95 从 200 ms 降至 120 ms”，卡片 `results` 只保留无前缀的“P95 从 200 ms 降至 120 ms”。`validate_field_sources` 用预测段或实测段作为 `quote` 都能通过，因为它证明字段值是引文子串、引文存在于该文档，不证明抽取时保留了限定词，也不裁定测量属性。现有 `fact_scope_v1` 的字段位置、来源 SHA 与实施/发布状态不能补回这层丢失的信息。**不能仅将旧 `field_sources` 当成实测的权威判断**；必须先在来源侧核对完整原命题与唯一语境，再谈结果状态与两个消费者如何复用。此为纯函数隔离观察，未触及 App 保存、正式生成或真实材料。

**结果真实性实施验收（规范已对齐，完整核定尚未实现）**：

1. **先定位命题，再判定发生性**。观察单元是 `卡 ID + results 字段内 index + Fact ID + 完整陈述 + 当前原文文档修订`，不是数字、整卡、句子关键词或 JD。现有 `evidence_fact_scope.py` 已核主体/对象/环境/实施/发布及 `evidence_sources.py` 的文档 SHA、精确引文是可复用的来源入口；但 `implemented`、`released`、`field_sources` 引文可定位或模型给出“测得”字样都不能单独证明**指标已经被测量**。当前没有可供生成和评分共同消费的权威测量结论，不把旧状态偷换成实测状态。
2. **独立检验完整来源语境**。正控须有可回读的现行原文，能够核实确有该结果的测量、对象/指标、环境及原材料明示的测量条件；只写测试环境就只能称测试环境结果。原文条件不完整时保留已证限定并标注未核，不脑补样本、基线、时间窗口或生产范围。若同一文档/同一卡同时含相同 P95 数字的预测与实测，必须凭**各自独立、唯一定位的原句及上下文**判定；相同数字、相同引用片段、只在其他字段里出现的结果或非唯一引文不能相互背书。对“模拟假设下”这类上下文限定，不得截掉限定再计实测。
3. **对照矩阵先于代码**。在同一当前来源文件里安排①同数字的真实测试实测、②预测、③目标、④模拟假设，另加入⑤无量化但已验证交付、⑥实测仅测试环境且生产未知、⑦同句混合实测与更强的生产断言、⑧源文 SHA 变化或重复引文无法指向位置。独立期望：①完整可证且限定保留才算量化；②③④不计已实现量化；⑤可作为 R3.1 结果而不强凑数字；⑥不升级生产；⑦不截句洗白；⑧无效化先前结论。由已核来源的语义和测量事实判定，而不是模型/规则从自身输出倒推真值。
4. **来源判定一次，两个消费者复用**。需要先证明既有证据复审能产生针对精确 Fact 和原文修订的、与自由文本输出独立的测量核定；然后才讨论在**既有复审快照**内如何表示及撤销该结论。不得新建第二套事实库、并行评估状态、审批队列或依赖某次模型输出自证。正文实际选用的完整声明与 R3.2 必须共同使用这一核定，不能生成可疑强断言再仅降低质量评分；现行 scope 正向正文未开放的安全约束继续有效。
5. **不把质量建议升级为投递许可**。来源失效、测量未知或无法唯一定位时不得计已实测量化；已完成的非数字成果继续可展示。质量建议仍属建议层，事实真伪和个人职责仍由既有来源及审批约束决定，不因分数提高而赋予自动投递权限。本次未新增接口/字段/存储表示，核定生产者和共享消费者仍待实现；不能把纯函数对照测试说成 D5 应用端到端验收。

## 5. 实施顺序

```
Phase A  标准与报告（无 LLM 变化）：specs → tiered_evaluator 规则部分 → quality_report 结构 → agent.py 接入 → 审批页展示
Phase B  LLM 判项与突出点：R1.4/R2.1/R3.1/R3.5/R4.1 → 提名与否决 → 真实 JD 回归（0 模型调用缓存路径）
Phase C  证据推断：provenance 字段/指纹 → 单文档元数据注入 → inferFields → 对账面板确认 → 用户在授权真实样本上确认
Phase D  生成降级措辞与首屏重排 → P0-026 目标 JD 重新生成 → 真实 App 两页 PDF 验收
```

A 可独立验收；B 依赖 A；C 与 A/B 并行开发但验收依赖用户确认；D 依赖 B、C。

## 6. 风险与缓解

| 风险 | 缓解 |
| --- | --- |
| L3 推断把任职期当项目期（10-17 试验已见） | 任职区间只作上限约束不作候选值；要求多文档共现才产出区间；置信度 < 0.5 折叠 |
| LLM 判项不稳定导致 auto_pass 抖动 | 判项缓存按版本指纹；同版本同输入不重判；失败项必须有引用，无引用判失败 |
| 标准过严导致永远不通过 | 阈值进 `config/quality/`；质量报告先于 auto_pass 上线一轮，观察真实分布再定阈值 |
| 用户确认负担 | 候选按置信度排序、支持批量接受高置信候选；每卡只提名一次，否决不重复 |
| 过渡期两套分数混淆 | `legacy_scores` 仅在折叠区显示，文案明示"不参与通过判定" |
